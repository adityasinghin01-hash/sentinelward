## 3. How big can it get (levels)
1. Single action (send alert) → 2. Fixed chain (detect → isolate → evidence → ticket) → 3. Agents that pick next steps within an allow-list (Fleet Hunt) → 4. Learning loop that improves playbooks from outcomes (A9).
Scale: one ward → whole hospital → many hospitals sharing anonymised attack fingerprints (one hack overloads neighbours — San Diego 2021 study) — FUTURE, mention in pitch only.

## 4. How data is used inside the automations (datathon angle)
- Escalation timers and nurse routing tuned from acknowledgement-time data (A1, A9).
- Device fault history → failure prediction (A6). Prior work: ML on maintenance records of 8,294 critical devices; patient-monitor failure prediction from inspection data (RF, SVM).
- Alarm counts per nurse → workload balancing (A7). Evidence: up to 310–771 alarms/patient/day; 83% of nurses feel overwhelmed; 55% saw an alarm nobody answered.
- Every agent action logged → audit trail + new training data (A9).
- Attack fingerprints → Fleet Hunt across same-model devices (A4).

## 6. Safety design for agents
1. Allow-list: agents can only call named actions (isolate device, send message, open ticket, save evidence). No shell, no treatment devices.
2. LLM writes words only from structured fields — never decides, never reads raw device text as instructions (prompt-injection guard).
3. Least privilege per agent (Containment can't send messages; Alert can't isolate).
4. One-click undo for every automatic action; every action logged with who/what/why.
5. Human sends anything official (CERT-In); human approves playbook changes.
