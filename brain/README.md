# SentinelWard live brain

One Python process consumes the locked doc-00 v1 MQTT messages, assembles per-bed 10-second windows every 5 seconds, publishes M1–M6 score envelopes and retained verdicts. Scores increase with suspicion. Live rules use `M<n>-live-2026-10-17`; configured M2 bundle scores use `M2-gbt-2026-10-17`. The window assembler and all inference adapters in this package were written on 2026-10-17.

Scoring starts with the service and continues whenever vitals arrive, including after a demo `reset`. Both `reset` and `run` clear inference memory and advance a generation token that discards in-flight results; `run` also records the run ID. Display snapshots survive these controls.

The approved decision precedence is BOTH, EMERGENCY, TAMPERING, DRIFTING, LOOSE_SENSOR, DEVICE_ATTACK, UNSURE, NORMAL. Confidence and trust are **uncalibrated** heuristic numbers. Trust is `1 - max(eligible M3, M4, M5)`; no eligible integrity check gives numeric 1 but the verdict remains UNSURE. Missing data never establishes normal physiology.

M1 checks observed ECG/PPG missingness, flat lines, clipping, implausible amplitudes and high frequency/powerline energy. M2 (`M2-gbt-2026-10-17`) scores the full 10-second pre-alarm window (ECG, PPG and ABP when present) with gradient-boosted trees trained on LinuxONE (`ml_v2/`, hash-pinned artifact, numpy-only inference) and a per-alarm-type threshold; the score only explains and never suppresses, delays or downgrades the alarm. When the pre-alarm window carries the optional v1.3 second ECG lead (`ecg2` at least half present), the 2-lead model `M2-gbt2-2026-10-17` (`ml_v2/artifacts/m2_gbt2_2026-10-17.json`, SHA-256 pinned, own per-type thresholds) runs instead; if that artifact fails its hash the 1-lead model runs. `extra.features.ecg_leads_used` says which. Without a full pre-alarm window, or if the artifact fails its hash, it falls back to the VTACH earlier seed and then the live ECG rule (`M2-live-2026-10-17`). M4 compares normalized, non-overlapping windows only with this bed's recent history and checks sequence repeats/regressions and authenticated sender metadata. Its optional earlier opinion remains in `extra`; unverified channel order prevents that earlier path.

The independent window assembler accepts contiguous one-second 125 Hz frames. A forward timestamp/sequence gap, device change or reset clears pending history. Duplicate and out-of-order chunks are rejected without changing accepted history. It emits complete ten-second windows every five seconds on the epoch grid, keeps null samples and channel-validity masks, and snapshots alarms and optional ABP samples.

An alarm is recorded before duplicate rejection and preserves EMERGENCY/BOTH through its 10-second window and another 30 seconds. A bedside `patient_ok` clears prior alarm memory; `patient_not_ok` forces emergency. Silence at 3 seconds gives offline UNSURE unless emergency or independently evidenced tampering takes precedence. Display snapshots survive reset separately from inference memory. Sequence gaps and silence alone never imply attack. Sender IDs are accepted only as out-of-band authenticated metadata; the ordinary MQTT subscriber cannot identify the publisher, and payload `device_id` is not sender proof.

## Local use

From the repository root:

```sh
python3 -m venv .venv
.venv/bin/pip install -e common -e brain -e attacks pytest
.venv/bin/pytest -q brain/tests attacks/tests common/tests
SW_MQTT_HOST=localhost .venv/bin/sw-brain
```

Credentials: `SW_MQTT_USERNAME`, `SW_MQTT_PASSWORD`; connection: `SW_MQTT_HOST`, `SW_MQTT_PORT`, `SW_MQTT_TLS=1`, optional `SW_MQTT_CA`. No credentials are stored in source. Vitals use QoS 0; scores, bedside/control/features and verdicts use QoS 1; only verdicts are retained.

The shared `sw_brain.io` seam uses `sw_common` topics, builders, decode/validation and MQTT `Bus`. Every outgoing envelope is checked before transport; invalid messages are rejected, counted in `invalid_outgoing` and logged. Services also count rejected direct inputs in `invalid_incoming`; the underlying shared Bus counts/logs invalid MQTT input in `bus.stats()['invalid']`. The adapter retains original payload sizes, arrival clocks and the bounded safety queue, including TLS with system trust roots when no CA file is supplied.

## Optional M2 bundle

Set `SW_M2_MODEL` to an operator-provided model file. Its SHA-256 sidecar must be `<model-file>.sha256` or the same filename with its suffix replaced by `.sha256`; the first whitespace-separated token is the 64-character hex digest. The digest is checked over the bytes that are deserialized, before any bundle or feature code executes. A sidecar detects mismatched bytes; only configure trusted pickle bundles and trusted feature code.

A pickle bundle is a dictionary with `model_version: "M2-gbt-2026-10-17"`, `model` (a binary estimator with `classes_` and `predict_proba`), ordered `feature_names`, and `thresholds` keyed by alarm code. The current portable JSON export (`format: "sentinelward-gbt-json-1"`, `baseline`, `trees`, and the same metadata) is also accepted without an additional estimator dependency. Pickle estimators require their own compatible runtime libraries.

The new `ml_v2/m2gbt/features.py` supplies `window_features(ecg, ppg=None, abp=None, alarm_code=None)` as a feature dictionary. It is located under an ancestor of the model file, or beside the model; `SW_M2_FEATURES` can specify its absolute path. Its package `__init__.py` supports relative imports. Inputs retain the native 125 Hz samples and nulls. Feature names determine vector order, and the saved threshold for the current alarm determines positivity.

Loading and inference share one worker thread with at most twelve pending requests and 128 cached results. Foreground scoring never waits for the worker. A missing bundle, sidecar, module or dependency, failed hash, wrong version, missing feature/threshold, invalid score, or pending task leaves the live rule in use with `extra.model_unavailable_reason`. Model results use the full pre-onset window when available, otherwise the first full window in that alarm episode, and are keyed by bed/device/window/alarm. Reset discards earlier generations. No model output can suppress or delay a monitor alarm's emergency precedence. Server validation still requires a real bundle, broker and LinuxONE measurements.

M3 compares observed ECG and PPG rates. It resolves a pulse autocorrelation half/double-rate alias using pulse peaks and the monitor HR when available; a regular, genuinely different pulse rate remains suspicious. Irregular nonharmonic estimates that disagree with the heartbeat are unavailable, not evidence of a clear body match. Timing learns the most stable plausible arrival during warmup, then compares pulse pairing candidates against that physical baseline as RR changes. Alternative historic pairings cannot hide a genuine arrival shift. Only consistent, non-overlapping, quality/clinical/transport-approved observations learn; large timing steps cannot train themselves away. Rate/timing mismatches need two distinct windows; one flat signal with present beats on the other remains immediate evidence. M3 also checks three distinct seconds of repeated PPG against a different ECG at sample resolution, including fractional-second offsets. Confirmed partial pulse replay remains suspicious until an explicit bedside `patient_ok` or reset clears it, because matching rates alone cannot prove source timing recovered; whole-waveform replay remains M4's responsibility. Reset clears all M3 evidence and baselines. M5 uses live receipt rules and fresh topic-7 features from the new extractor at `net/device/<id>/features`. Flood rate above 5 messages/s scores .95, at least two sequence repeats score .9, and multiple senders score .6. Evidence from either source can raise the score; topic-7 measurements retain their own window and feature fields in `extra`, while receipt features retain their ten-second span. Stale or future extractor windows are ignored. Gaps or silence alone never establish an attack. Standard MQTT does not expose sender IDs; authenticated extractor metadata supplies topic-7 sender counts.

M6 pairs arterial samples with distinct, fresh cuff readings and learns this patient's normal gap. Two cuff readings establish the initial pressure baseline; only small consistent changes update it. Both pressures falling together does not establish drift. A cuff MAP and current arterial mean both below 65 mmHg remain an independent emergency check even when M2 is not applicable. Cuff comparisons expire after five minutes. Every ineligible model publishes `score: null`, `extra.eligible=false` and `extra.unavailable_reason`, including missing inputs, warmup, expired comparisons and detector failures. All six score envelopes are published every five seconds, and retained `verdict.scores` includes all six models with null values for ineligible models. No unknown score is replaced with zero. M6 without arterial samples in the current window and M2 without a monitor alarm in or just before the window additionally retain `extra.not_applicable=true` and an explanatory reason. NORMAL requires every applicable check to be eligible and clear, no active alarm, and an online monitor. Not-applicable checks do not block NORMAL or baseline learning; an applicable unknown check still prevents NORMAL. Null scores are ignored by trust. Numeric zero is reserved for an eligible, computed score.

`BrainService.snapshots` retains latest accepted values; `last_trusted_snapshots` stores a separate copy only after NORMAL, and `display_snapshot(bed)` selects that copy when currently untrusted. Reset preserves display copies while clearing inference memory. Alarm and bedside/control messages have reserved bounded storage when the normal receive queue fills. Older bedside/control messages cannot undo newer safety state.

The approved alarm-preservation rule takes precedence over doc-12's expected B04 LOOSE_SENSOR and B06 TAMPERING while their ASYSTOLE alarms are active: these are EMERGENCY or BOTH until bedside `patient_ok` or alarm-hold expiry. The process only publishes scores/verdicts; agent actions, isolation, undo and official report sending belong to their existing owners.

Baseline admissions require current usable signals and clean clinical/network/replay checks. Consecutive frames for the same alarm episode keep its original pre-onset window.

On this Mac, Python 3.14 skipped the editable-install `.pth` files because the filesystem marked them hidden. If imports fail immediately after reinstalling locally, inspect `ls -lO .venv/lib/python*/site-packages/__editable__*.pth`; clear that local flag with `chflags nohidden .venv/lib/python*/site-packages/__editable__*.pth`. This is a local venv setup step; LinuxONE uses its native Python environment.
